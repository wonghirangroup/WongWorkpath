## ภาพรวมความเป็นแบรนด์เฉพาะตัว

**ไม่ใช่แอปเทมเพลตทั่วไป** — สีส้ม, choreography หน้า Login, ผังองค์กรแบบ pan/zoom, รูปแบบรหัสโครงการ `GS-69-P-001`, ปีพ.ศ. เกือบทุกที่ — ล้วนออกแบบมาเฉพาะสำหรับบริษัทนี้จริงๆ ไม่ใช่ลอกแบบมา จุดที่ยัง "เหมือนแอปไหนก็ได้": กรอบ Modal มาตรฐาน และ `<input type="date">` ดั้งเดิมของเบราว์เซอร์

**สแกนอัตโนมัติ (CLI):** เจอ 6 จุด แต่ตรวจแล้ว **5 ใน 6 เป็น False Positive** (ตัว detector อ่าน className ตรงๆ ไม่รู้ context):
- "รูป broken" ใน `EmployeeAvatar.tsx` — จริงๆ ไม่มี `<img>` เลย เป็นแค่ข้อความในคอมเมนต์ที่ดันมีคำว่า `<img src="">` อยู่
- "เทาบนพื้นสี" 4 จุด — ทุกจุดเป็นเงื่อนไข ternary/hover/disabled ที่สีเทากับสีพื้นไม่มีทางขึ้นพร้อมกันจริง
- เหลือจริงแค่ 1 จุด (bounce animation ที่จุดโหลด login) ซึ่งเป็นแบบที่ยอมรับได้สำหรับ widget ประเภทนี้

**สแกนจากเบราว์เซอร์จริง (คนละชุดกับ CLI ด้านบน):** ต่างจากสแกน CLI เพราะเช็คสีที่ Render จริง ไม่ใช่แค่เดาจาก className — เจอ contrast ต่ำ/ตัวหนังสือเล็กเกิน (9-10px) กระจายทั่วแอป โดยเฉพาะ **หน้าปฏิทิน (47 จุด)** และ **ผังองค์กร (33 จุด รวม nested-card ซ้อนกัน 16 จุด)** — อันนี้น่าเชื่อถือกว่าสแกน CLI เพราะเป็นข้อมูลจากการ render จริง ไม่ใช่เดาจาก class

ไม่มีการเปิด overlay ค้างไว้ในเบราว์เซอร์ของคุณนะครับ — ทีมตรวจใช้ Playwright อัตโนมัติเบื้องหลัง ไม่ใช่หน้าต่างที่คุณเห็น ผลที่ได้คือรายงาน+screenshot เท่านั้น

## ภาพรวมสั้นๆ

พื้นฐานดีเซอร์ไพรส์กว่าที่คิดสำหรับ internal tool — ระบบดีไซน์มีวินัย จัดการ error ดี หน้า Login ทำมาประณีต แต่**เรื่อง "ควบคุมออกจาก UI"** (Esc, focus keyboard) กับ**ความหนาแน่นของบางหน้า** (Project Board, Calendar, ผังองค์กร) เป็นรอยแตกที่ชัดที่สุด และมี**บั๊กจุดเล็กที่ "แปลก" ตามที่ถาม**อยู่จริงหลายจุด (ด้านล่าง)

## จุดที่ทำได้ดี

1. **ระบบดีไซน์เข้าใจตัวเองดี** — `Design.md` เขียนตรงกับโค้ดจริง ไม่ใช่เอกสารในฝัน
2. **จัดการ error รอบคอบ** — เปลี่ยนชื่อซ้ำอัตโนมัติ+แจ้งเตือน, ฟอร์มไม่ล้างตอน error, validate วันที่แบบ inline
3. **หน้า Login ลงทุนสูง** — choreography เข้าเรื่อง, toggle ตา animate, shake ตอน login ผิด, OTP ครบวงจร

## ปัญหาหลัก (เรียงตามผลกระทบ)

**[P1] กด Esc ปิด Modal ไม่ได้เลยสักอัน + คลิก backdrop ปิดได้บ้างไม่ได้บ้าง**
- **อะไร**: ทดสอบสดแล้ว — CreateProjectModal, AddTaskModal, EditProjectModal, ScheduleMeetingModal ไม่ตอบสนอง Esc เลย (ตรวจโค้ดยืนยัน 0 จุดมี keydown handler) ส่วนคลิก backdrop ปิดได้เฉพาะ TaskDetailModal/CancelMeetingModal แต่ปิดไม่ได้ใน 4 ตัวข้างต้น (ตั้งใจปิดไว้กันคลิกโดนพื้นหลังแล้วข้อมูลหาย)
- **ทำไมสำคัญ**: Esc ปิด popup เป็นธรรมเนียมเว็บสากล แอปนี้ใช้ทุกวัน ยิ่งเจอบ่อยยิ่งสะสมความหงุดหงิด และคนใช้คีย์บอร์ดล้วนต้องไล่เมาส์หาปุ่ม X เล็กๆ ทุกครั้ง
- **แก้**: มี pattern ที่ถูกต้องอยู่แล้วใน ProjectDetail's ขยาย/ย่อ กับแผงแจ้งเตือนใน Header — ดึง hook เดียวกันมาใช้กับทุก Modal ที่ผ่าน `createPortal`

**[P1] ชื่อโครงการในตารางดูเหมือนกดได้ แต่กดไม่ได้จริง**
- **อะไร**: ทีมตรวจสอบ B พยายามกดที่ตัวหนังสือชื่อโครงการ (ตัวหนา ดูเหมือนลิงก์) ตามสัญชาตญาณ แล้วไม่มีอะไรเกิดขึ้น — สคริปต์ทดสอบเสียเวลาหาแท็บที่ไม่เคยเปิดออกมา 30 วินาทีก่อนจะรู้ว่าต้องกดปุ่ม "ดูรายละเอียด" (ไอคอนตาเล็กๆ) ที่อยู่คนละคอลัมน์แทน — เป็นกรณีจริงของ "หุ่นยนต์เองยังเดาผิด"
- **ทำไมสำคัญ**: องค์ประกอบที่เด่นที่สุด ดูคลิกได้ที่สุดในแถว (ตัวหนา) กลับไม่ใช่จุดที่คลิกได้จริง ขัดกับ Heuristic "จำได้ไม่ต้องนึก" ตรงๆ
- **แก้**: ทำให้ชื่อโครงการในตารางกดเปิดรายละเอียดได้เลย (หรืออย่างน้อย cursor-pointer + hover state ให้รู้ว่ากดได้)

**[P1] Contrast ต่ำ/ตัวหนังสือเล็กเกิน กระจุกหนักที่บางหน้า**
- **อะไร**: สแกนจากเบราว์เซอร์จริงเจอ contrast ต่ำ/ตัวเล็ก (9-10px) เยอะสุดที่ **หน้าปฏิทิน (47 จุด)** และ **ผังองค์กร (33 จุด)** ประกอบกับไม่มี focus outline ที่มองเห็นได้เลยสักจุดในทั้งแอป (`focus:outline-none` 81 จุด, `focus-visible` 0 จุด) — ปุ่มสลับมุมมอง, แท็บกรองสถานะ, ปุ่มเรียงลำดับ ล้วนกดคีย์บอร์ด Tab ไปแล้วมองไม่เห็นว่าอยู่ตรงไหน
- **ทำไมสำคัญ**: คนใช้คีย์บอร์ดหรือสายตาไม่ดีจะหลงในหน้าที่ใช้บ่อยที่สุด (ปฏิทิน) และ Design.md เองก็ยอมรับไว้แล้วว่าสีตัวหนังสือบน pill สถานะบางสีไม่ผ่าน WCAG AA
- **แก้**: เพิ่ม `focus-visible:ring-2` ให้ปุ่ม/แท็บที่ตัด outline ออกไป, ไล่เช็ค contrast จริงที่หน้าปฏิทินก่อนเพราะเจอเยอะสุด

**[P2] รูปแบบวันที่ไม่ตรงกันทั้งแอป (3-4 แบบ)**
- **อะไร**: หน้า Dashboard/Project Board/Project Detail ใช้ไทยเต็ม ("01 ก.ย. 2569"), หน้าปฏิทินฝั่ง sidebar โชว์ ISO ดิบ ("2026-09-16 02:15"), หน้าเอกสาร Drive โชว์เลขสั้นแบบพ.ศ. ("2/7/2569"), ส่วนช่องกรอกวันที่ (`<input type="date">`) โชว์ mm/dd/yyyy แบบฝรั่ง — รวมแล้ว 4 รูปแบบ
- **ทำไมสำคัญ**: แอปนี้ทำเรื่อง localization ละเอียดมากทุกที่ ยกเว้นตรงนี้ที่ผู้ใช้จะรู้สึก "ทำไมอยู่ๆ ถึงเป็นภาษาอังกฤษ/ตัวเลขแปลกๆ"
- **แก้**: เลือกรูปแบบเดียว (แนะนำแบบไทยเต็มที่ใช้เป็นส่วนใหญ่แล้ว) ใช้ให้ทั่วแอป และแทนที่ `<input type="date">` ด้วย component ของตัวเองที่มีอยู่แล้ว (เหมือน Dropdown)

**[P2] Project Board และหน้าที่ซับซ้อน แน่นเกินไปในมุมมองเดียว**
- **อะไร**: แถบกรองสถานะ (`ProjectFilterTabs`) มี "ทั้งหมด + ใกล้ครบกำหนด + 7 สถานะพื้นฐาน + สถานะที่ Admin เพิ่มเอง" รวมกันแถวเดียว (เจอ 9 แท็บตอนทดสอบ และเพิ่มได้ไม่จำกัดผ่านเมนูปรับแต่งการ์ด) วางอยู่ใต้การ์ดสรุปสถานะ 5 ใบ กับ Toolbar 5 ปุ่ม — ก่อนจะเห็นแถวโครงการแถวแรกด้วยซ้ำ
- **ทำไมสำคัญ**: หลักการ "จำได้ 4 อย่างพร้อมกันในหัว" ถูกฝ่าไปแล้วตั้งแต่ก่อนเริ่มงาน และปัญหาจะหนักขึ้นเรื่อยๆ เพราะ Admin เพิ่มสถานะได้ไม่จำกัด ไม่มีวันดีขึ้นเอง
- **แก้**: จำกัดแท็บที่โชว์พร้อมกัน (~5-6) แล้วซ่อนที่เหลือในเมนู หรือให้ตัวเลือก "สถานะไหนโชว์การ์ด" ควบคุมแท็บไปด้วยเลย

## ปัญหาแปลกๆ ที่เจอจริง (ตรงตามที่ถาม — บั๊กเล็กระหว่างเดินดู flow)

- **แท็บ "การประชุม" ในหน้าโครงการ**: เวลาสิ้นสุดกับสถานที่ประชุมข้อความชนกันไม่มีช่องว่างในตาราง เช่น `10:00 - 11:00Meeting Roo...` (ถูกตัดด้วย)
- **แท็บ Timeline**: ปุ่มสลับมุมมอง วัน/เดือน/ปี ถูกตัดที่ขอบขวาจอ เห็นแค่ "วัน" กับ "เดือน" ครึ่งเดียว ตัวที่ 3 หายไปเลย (จอ 1440px)
- **แท็บ "ทีม"**: ถ้ามีสมาชิกแค่คนเดียว การ์ดจะลอยอยู่ตรงกลางพื้นที่ว่างเปล่าขนาดใหญ่ พร้อมข้อความ "สมาชิกที่เหลือคือผู้รับผิดชอบหลักด้านบนแล้ว" ที่ดูเหมือนหลุดมาไม่มีที่ไป
- **หน้ารายการโครงการ (list view)**: คอลัมน์ขวาสุด (วันที่เริ่ม) ถูกตัดที่ขอบตาราง ข้อความขาดกลางคำ ("01 ก.ย. 2...") แทนที่จะเลื่อนดูได้
- **ลาก-วางย้ายไฟล์ใน Doc Vault**: ยืนยันในโค้ดแล้วว่าไม่มี toast แจ้งผลสำเร็จ ทั้งที่ mutation อื่นทุกจุดในไฟล์เดียวกันมี toast หมด
