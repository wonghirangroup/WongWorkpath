# Master Data — ค่าคงที่และข้อมูลอ้างอิงของระบบ

รวมค่า enum/รายการอ้างอิงที่ตายตัวหรือกึ่งตายตัวในระบบ ตรวจกับโค้ดจริงและฐานข้อมูลจริง ณ 2569-09-25

## ระดับบัญชีผู้ใช้ (AccountType)

| ค่า | ชื่อแสดงผล | ข้อจำกัดจำนวน |
|---|---|---|
| `employee` | พนักงาน | ไม่จำกัด |
| `admin` | Admin | ไม่จำกัด |
| `superadmin` | Super Admin | **สูงสุด 1 คน** (singleton — ตั้งคนใหม่ลดคนเดิมอัตโนมัติ) |
| `executive` | ผู้บริหาร | **สูงสุด 2 คน** |

ที่มา: `src/types.ts` (`ACCOUNT_TYPES`), บังคับจริงที่ `server/routes/employees.ts` (`accountTypeChangeError`)

## ประเภทโครงการ (ProjectType)

| รหัส | ชื่อเต็ม |
|---|---|
| P | โครงการ |
| SP | โครงการย่อย (ต้องมีโครงการหลักเป็นประเภท P) |
| I | นวัตกรรม |
| C | ที่ปรึกษา |
| B | ออกบูธ |
| FND | ทุน |

นอกจากนี้ผู้ใช้เพิ่มประเภทเองได้ผ่านตาราง `project_custom_type` (ปัจจุบันยังไม่มีรายการที่สร้างเอง — 0 แถวในฐานข้อมูลจริง)

## สถานะโครงการ (ProjectStatus)

`draft` (ร่าง) → `pending_review` (รอตรวจสอบ) → `in_progress` (กำลังดำเนินการ) → `on_hold` (พักไว้) / `completed` (เสร็จสิ้น) / `cancelled` (ยกเลิก) / `idea` (แนวคิด)

โครงการใหม่เริ่มที่ `draft` เสมอ และเปลี่ยนเป็น `in_progress` อัตโนมัติทันทีที่มีงานแรกถูกสร้างในโครงการนั้น ผู้ใช้ยังเพิ่มสถานะเองได้ผ่านตาราง `project_custom_status` (ปัจจุบัน 0 แถวที่สร้างเอง) — สถานะที่สร้างเองลบไม่ได้ถ้ายังมีโครงการใช้อยู่ (409)

## ระดับความสำคัญ (ProjectPriority)

ตัวเลข 1–5 ใช้ร่วมกันทั้งโครงการและงาน โดย **1 = สำคัญที่สุด, 5 = สำคัญน้อยที่สุด** (ยิ่งเลขน้อยยิ่งสำคัญ)

## สถานะงาน (ProjectTaskStatus)

| ค่า | ชื่อแสดงผล | ที่มา |
|---|---|---|
| `todo` | ยังไม่เริ่ม | ไม่มีผู้รับผิดชอบ |
| `in_progress` | กำลังทำ | มีผู้รับผิดชอบแล้ว |
| `review` | รอตรวจ | ผู้รับผิดชอบกด "ส่งงาน" |
| `blocked` | ติดปัญหา | ตั้งเองผ่านช่องติ๊ก (ต้องระบุเหตุผล) |
| `done` | เสร็จแล้ว | ผู้ตรวจกด "ผ่าน" |

งานที่มีงานย่อย (หัวข้อ) สถานะคำนวณจากงานย่อยเสมอ: มีงานย่อยที่ยังไม่เสร็จ = กำลังทำ, งานย่อยเสร็จครบ = เสร็จแล้ว

## ประเภทและขอบเขตของรหัสผ่าน (Credential)

**ประเภท (type):** Username & Password / API Key / Bank Account / Access Token
**ขอบเขต (scope):**

| ค่า | เห็นได้โดย |
|---|---|
| ส่วนตัว | เฉพาะผู้สร้าง |
| ทีม | คนในแผนกเดียวกับผู้สร้าง (ผู้บริหารเห็นทุกทีม) |
| โครงการ | เจ้าของ/สมาชิกของโครงการนั้น (ผู้บริหารเห็นทุกโครงการ) |

## ประเภทและขอบเขตของเอกสาร (Document)

**ประเภท (kind):** folder / file / link
**ขอบเขต (scope):** ส่วนตัว (เฉพาะผู้สร้าง) / โครงการ (เจ้าของ/สมาชิกโครงการนั้น)

## หมวดการแจ้งเตือน (NotificationCategory)

| ค่า | ความหมาย |
|---|---|
| assignment | ได้รับมอบหมายงาน/ตั้งเป็นผู้รับผิดชอบหลัก |
| review | ผลการตรวจงาน / มีงานรอตรวจ |
| blocked | งานติดปัญหา |
| deadline | ใกล้ครบกำหนดส่ง/สิ้นสุดโครงการ, เลยกำหนดส่ง |
| meeting | นัดประชุมใหม่/ยกเลิก/เตือนก่อนถึงเวลา |
| approval | คำขอแก้ไข/ลบที่รออนุมัติ และผลการพิจารณา |

ผู้ใช้ปิดการแจ้งเตือนแต่ละหมวดได้เองที่ ตั้งค่า → การแจ้งเตือน (เก็บใน `employee.muted_notification_categories`)

## ประเภทข้อความแจ้งเตือน (Notification.type)

`info` (ทั่วไป) / `success` (สำเร็จ) / `warning` (ต้องระวัง/ต้องทำอะไรต่อ)

## ช่วงเวลาแจ้งเตือนล่วงหน้าที่ตั้งได้ (Deadline Reminder)

ตัวเลือกสำเร็จรูป: 1 วัน / 3 วัน / 7 วัน / 1 เดือน (30 วัน) / 3 เดือน (90 วัน) หรือกำหนดเอง 1–365 วัน สูงสุด **6 ช่วงต่อรายการ** ค่าเริ่มต้นเมื่อไม่ได้ตั้งเองคือ **เหลือ 2 วัน** และตั้งได้ไม่เกินจำนวนวันจริงระหว่างวันเริ่มกับวันกำหนดของรายการนั้น

## สถานะนัดประชุม (Meeting.status)

`scheduled` (นัดปกติ) / `cancelled` (ยกเลิกแล้ว — เก็บเหตุผลไว้ที่ `cancellation_reason`)

## สถานะและประเภทคำขออนุมัติ (ChangeRequest)

- **entity_type:** project / project_task / employee
- **request_type:** edit / delete (คำขอของพนักงานเองมีได้แค่ edit เรื่องชื่อ-ชื่อเล่นเท่านั้น)
- **status:** pending / approved / rejected

## ผังองค์กรจริงปัจจุบัน (5 ฝ่าย / 10 แผนก)

| ฝ่าย | แผนก |
|---|---|
| ฝ่ายบริหารและสนับสนุน | แผนกบุคคล, แผนกการเงินและการบัญชี |
| ฝ่ายจัดซื้อและควบคุมสินค้า | แผนกจัดซื้อ, แผนกควบคุมสินค้าและสต็อก |
| ฝ่ายขายและปฏิบัติการ | แผนกขายและดูแลลูกค้า, แผนกปฏิบัติการคลังและขนส่ง |
| ฝ่ายการตลาดและออนไลน์ | แผนกธุรการการตลาด, แผนกออนไลน์ |
| ฝ่ายพัฒนาและไอที | แผนกพัฒนาธุรกิจและองค์กร, แผนกเทคโนโลยีและไอที |

ที่มา: `src/data/orgStructure.ts` (`DEFAULT_ORG_DIVISIONS`) ตรงกับข้อมูลจริงในตาราง `org_division`/`org_section` (5/10 แถว) แก้ไขได้จากหน้า จัดการพนักงาน → โครงสร้างองค์กร (เฉพาะ Super Admin/ผู้บริหาร)

## จำนวนแถวข้อมูลอ้างอิงในฐานข้อมูลจริง (ณ วันตรวจสอบ)

| ตาราง | จำนวน |
|---|---|
| project_custom_status | 0 (ยังไม่มีใครสร้างสถานะเอง) |
| project_custom_type | 0 (ยังไม่มีใครสร้างประเภทเอง) |
| org_division | 5 |
| org_section | 10 |
