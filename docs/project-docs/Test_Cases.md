# Test Cases

## หมายเหตุสำคัญ

**โปรเจกต์นี้ไม่มีชุดทดสอบอัตโนมัติ** (ไม่มี Jest/Vitest/Playwright ติดตั้งถาวร ไม่มีสคริปต์ `test`) การตรวจสอบความถูกต้องทำ 2 ทาง:

1. `npm run lint` (`tsc --noEmit`) — ตรวจ type หลังแก้โค้ดทุกครั้ง
2. ทดสอบมือ (manual) ผ่านเบราว์เซอร์จริงด้วย Playwright ที่ติดตั้งชั่วคราว — ใช้บัญชี/ข้อมูลที่ขึ้นต้น `E2E_`/`e2e_` แล้วลบทิ้งหลังทดสอบ

เอกสารนี้รวบรวม test case หลักที่เคยใช้ทดสอบจริงและควรทดสอบซ้ำทุกครั้งที่แก้ไขส่วนที่เกี่ยวข้อง เป็นฐานสำหรับเขียนเป็นชุดทดสอบอัตโนมัติในอนาคตได้

## กลุ่ม A: การยืนยันตัวตน (Authentication)

| ID | สถานการณ์ | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| A-01 | ล็อกอินสำเร็จ | กรอก username/password ถูกต้อง | ได้ token, เข้าหน้าแดชบอร์ด |
| A-02 | ล็อกอินผิด | กรอกรหัสผ่านผิด | ขึ้นข้อความผิดพลาด ไม่ได้ token |
| A-03 | ล็อกอินผิดเกินจำนวน | ลองผิด 6 ครั้งติดกันภายใน 15 นาที | ได้ 429 ถูกปฏิเสธชั่วคราว |
| A-04 | ลืมรหัสผ่าน → OTP → ตั้งใหม่ | ขอ OTP → กรอกถูกต้อง → ตั้งรหัสใหม่ | ตั้งรหัสผ่านสำเร็จ ล็อกอินด้วยรหัสใหม่ได้ |
| A-05 | OTP หมดอายุ | รอเกิน 10 นาทีแล้วกรอก OTP | ถูกปฏิเสธ ต้องขอใหม่ |
| A-06 | session หมดอายุ | ใช้ token เก่า/ปลอม เรียก API | ได้ 401 เด้งกลับหน้า login พร้อมข้อความ "เซสชันหมดอายุ" |

## กลุ่ม B: สิทธิ์การใช้งาน (Permission)

| ID | สถานการณ์ | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| B-01 | พนักงานทั่วไปลบโครงการของตัวเอง | เรียก `DELETE /api/projects/:id` ด้วยบัญชีพนักงานที่เป็นเจ้าของ | 403 — ลบได้เฉพาะ Admin ขึ้นไป |
| B-02 | Admin ลบโครงการที่ตัวเองไม่ใช่เจ้าของ | เรียก DELETE ด้วยบัญชี Admin | 409 พร้อม `requiresApproval: true` |
| B-03 | เจ้าของอนุมัติคำขอลบ | ยื่นคำขอ → เจ้าของกดอนุมัติ | โครงการถูกลบจริง คืนผลลัพธ์ 200 ไม่ใช่ 500 |
| B-04 | ลบนัดประชุมโดยคนอื่น | บัญชีที่ไม่ใช่ผู้สร้างนัดเรียก `DELETE /api/meetings/:id` | 403 |
| B-05 | ผู้สร้างนัดลบนัดประชุมของตัวเอง | เรียก DELETE ด้วยผู้สร้างนัด | 204 |
| B-06 | ปลอมชื่อผู้ทำรายการใน audit log | ส่ง `user`/`role` ปลอมไปที่ `POST /api/audit-logs` | ระบบบันทึกชื่อจากบัญชีที่ล็อกอินจริงเสมอ ไม่ใช่ค่าที่ส่งมา |
| B-07 | Admin กำหนดสิทธิ์ระดับสูง | Admin ธรรมดาพยายามตั้งคนอื่นเป็น superadmin/executive | ถูกปฏิเสธ ทำได้แค่ระดับ employee |
| B-08 | ตั้งผู้บริหารคนที่ 3 | Super Admin ตั้งผู้บริหารคนที่ 3 ขณะมีอยู่แล้ว 2 คน | ถูกปฏิเสธพร้อมข้อความให้ลดตำแหน่งคนเดิมก่อน |
